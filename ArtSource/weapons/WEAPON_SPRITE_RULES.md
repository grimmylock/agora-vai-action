# Weapon sprite rules (decided with Yan, 2026-11-13) - read this before touching any gun picture

Yan: "make double size the standard for every gun ... save the rules so that we don't need to revisit them every time we do a weapon sprite". Which guns are done: `WEAPON_STATUS.md` (generated, with each gun's real length and planned picture length); the planned sizes of all guns: `WEAPON_SIZE_CHART.png`.

## The standard
1. **One picture per gun, double size.** The menu/inventory picture `Assets/Resources/Sprites/Weapons/weapon_<Key>_hd.png` is a **160x64 canvas** with the gun centred, **twice the old size** (old 64x32 picture content width x 2: e.g. 124x30 for the Halden lever shotgun) BUT the gun's LENGTH is set from the REAL gun (Yan, 2026-11-13: "relative to the real world sizes, an smg is generally shorter than a rifle or assault rifle, shotguns depends on the model"): **length in px = 102 x (real overall length in cm / 29) ^ 0.28, capped at 156**, with the real lengths in `gun_real_sizes.json` (approximate, from memory, Yan reviews them in `WEAPON_SIZE_CHART.png`; the length is for the state the picture shows, stock folded or extended). The exponent compresses the real range (16-145 cm) into 87-156 px so a pistol still has room for detail; the Rinaldi (29 cm) = 102 px anchors it and the lever rifles (95 cm) come out at 142. To make the spread bigger change the exponent AND the canvas width. Height follows the still's proportions. The in-hand size is unchanged (k = new width / old in-hand width). The old tiny in-hand picture (`weapon_<Key>.png`, about 22-40 px) is NOT used any more for a reworked gun: the character holds the same double-size picture, drawn at the old on-screen size.
2. **Why double:** the first try shrank a SpriteCook still to the old 51x27 and it worked for a compact revolver but a long thin lever gun lost its lever loop, receiver and stock curve at 60x14. Double size keeps them. Do not go back to 64x32 for a long gun.
3. **Size on screen is unchanged:** the HUD weapon card (`HudView.cs:178`, 184x92, `preserveAspect`) and the inventory icons (`HudView.Pack.cs`) fit any texture into their box, so a bigger texture just shows sharper. In the hand the per-gun density does it (`WeaponArt.Dense`, `HeldWeapon.cs`): the sprite is made with pixels-per-unit 32 x k, k = new content width / old in-hand width, so the gun is as long on screen as before.
4. **Grip, support and muzzle points** (`WeaponArt.Grips`) of a reworked gun are in **virtual pixels** = texture pixels / k, so `HeldPoseMath` and the muzzle offset need no change. `make_gun_x2.py` prints the row, mapping the old row by position on the gun; always check it with `Tools/render/held_hires_check.py` (glove on the grip, support hand under the fore-end, muzzle at the barrel end).
5. **Reload pieces** (magazine, cylinder, break-action barrels cut by `mags.py`) do NOT exist for a reworked gun yet: `WeaponArt.Mag/Cylinder` return nothing for a dense gun, so its reload is the hands alone. Yan: "we'll animate weapon parts later". When that is done, cut the pieces from the double-size picture, same size and pivot as the gun.

## How to rework a gun (the pipeline)
1. **Reference photo(s) of the REAL gun.** Side-on, level, a clean background, the right model (the Nightwalker's first reference was the wrong Marlin). Real guns are drawing references only: never shown, never named in anything the player sees (rule 1 of CLAUDE.md). Record author, source and licence in `ArtSource/external/SOURCES.md` (and the reference file under `ArtSource/weapons/spritecook_pilot/`). Photos from `ArtSource/weapons/CREDITS.txt` first; Wikimedia needs `commons.wikimedia.org` + `upload.wikimedia.org` allowed and standard thumbnail widths (960/1280); it rate-limits (429), retry slowly.
2. **Prepare the reference:** rotate level, mirror so the muzzle points RIGHT, crop to the gun, scale every gun to the same width, stack 3-4 guns in ONE white sheet (never the game sprites as the reference: that only copies them).
3. **SpriteCook** (`ArtSource/spritecook_mcp.py`, MCP tool `generate_game_art`): `reference_asset_id` = the sheet (imported with `import_asset`), `pixel` true, `bg_mode` transparent, 2 variations, size about 256x192; the prompt describes each gun by SHAPE only, row by row (stock, receiver, lever, handguard...), "no text, no lettering, no logos". About 24 credits for the sheet. It returns the guns in the row order; the output size is its own (150-270 px), not the one asked for.
4. **Pick the better variation** by comparing each gun with its photo (stock shape, lever, receiver, colours, the defining feature: e.g. the Rinaldi's low bore was missed by both).
5. **`python3 ArtSource/weapons/make_gun_x2.py <Key> <still.png> [--lift TOP GAMMA] [--thicken X0 N]`**: crops, area-average downscales to 2x the old menu width, 16 colours, 14,14,18 outline, writes the 160x64 `_hd` and backs the old one up. `--lift 110 0.85` for black guns (they come out too dark otherwise; a strong lift turns them blue-grey), `--thicken` adds barrel rows when a slender barrel comes out 1-2 px too slim (Yan on the Frontier rifle). New guns need a row in `gun_x2_targets.json` first (old menu content width, old in-hand canvas, old Grips row in old px).
6. **Paste the two printed lines** into `HeldWeapon.cs` (`Dense` and the `Grips` row), run `python3 ArtSource/weapons/make_weapon_status.py`, run `held_hires_check.py` (`dotnet /tmp/test.dll heldframes f.json` first; add the gun to the `guns` list in `HeldFrames` in `Tools/compile_check/test/Program.cs`) and the harness checks (the `WeaponArt` check lists the dense guns).
7. **Log it** in `ArtSource/WORK_LOG.md`, show Yan the result next to the photo and the old sprite, say plainly what was not checked (Unity).

## Things that went wrong (do not repeat)
- Shrinking a SpriteCook still by hand-picking colours: use the area-average script, a plain nearest/majority shrink gives mush or a too-dark gun.
- Using the game sprite as the SpriteCook reference (edit mode): near-copy, softer and ~10% bigger. The reference must be the real gun.
- `ArtSource/weapons/hand/export_hand.py` regenerates `_hd` from `guns/<Key>.py` and would overwrite a reworked picture: do not run it for a reworked gun.
- Showing guns at different zooms: compare everything at the same on-screen width.
